### Item 2 — Proxy software fallback was broken (AM-001, P0) {#item-2}
- **Evidence:** `config/rendering.yaml` ships `proxy.codec: h264_nvenc`, `preset: p4`. `resolve_codec` correctly falls back to libx264 when NVENC can't open (§95), but `codec_arguments` passed the preset unchanged. Reproduced: `ffmpeg … -c:v libx264 -preset p4 -crf 28` → `x264 [error]: invalid preset 'p4'`, exit 234. FFmpeg's `libx264.c` passes `-preset` to `x264_param_default_preset` and returns EINVAL on an unknown name. So the fallback that exists to keep an import alive failed every proxy segment, which is what made ~125 baseline integration tests fail here. On the owner's machine it would surface the day NVENC stops opening (the encoder docstring already records a driver that was "a version too old").
- **Action:** `backend/media/proxy.py::codec_arguments` maps an NVENC `pN` preset reaching a software encoder to `veryfast`, the mirror of the existing software→`p4` rule. Test `test_an_nvenc_preset_on_the_software_fallback_is_mapped_not_passed` (fails on `b034df8`, passes after).
- **Measured:** 30 s synthetic 1080p60 (`testsrc2`) → 720p30 proxy through `generate_proxy` with the shipped config: **12.42 s, libx264 veryfast crf 28, 2.49 MB, largest process RSS 226 MB**, ffprobe: h264 1280×720 30/1 + aac, 30.000 s. Before the fix: no proxy (exit 234).
- **Status:** Implemented but not fully verified — targeted and previously failing integration files re-run (section 4); the full suite was not re-run to completion inside the budget, and not on Windows.

### Item 3 — Master limiter defeated its own ceiling (AM-002, P0) {#item-3}
- **Evidence:** the mix ends `loudnorm=I=-14:TP=-1:LRA=11` → `alimiter=limit=0.9661` (ceiling -0.3 dB). FFmpeg docs: alimiter `level` "Auto level output signal. Default is enabled. This normalizes audio back to 0dB"; `af_alimiter.c`: `level = s->auto_level ? 1 / limit : 1`. Measured on a hot transient signal (lavfi `aevalsrc`, ebur128 true peak, FFmpeg 6.1.1):

  | chain | true peak | integrated |
  | --- | ---: | ---: |
  | alimiter -0.3 dB (default level) | **0.0 dBFS** | -10.9 LUFS |
  | alimiter -0.3 dB, `level=disabled` | **-0.3 dBFS** | -11.2 LUFS |
  | loudnorm TP=-1 → alimiter (default) — the shipped chain | **-0.7 dBFS** | -13.6 LUFS |
  | loudnorm TP=-1 → alimiter `level=disabled` | **-1.0 dBFS** | -13.9 LUFS |

  So every rendered video got a fixed +0.3 dB after loudnorm, peaks above loudnorm's true-peak target, and the limiter could output full-scale.
- **Action:** `backend/rendering/audio_mix.py` adds `:level=disabled`. Tests: unit `test_the_limiter_does_not_auto_level_past_its_ceiling` and ffmpeg-backed `TestTruePeak::test_the_shipped_limiter_holds_its_ceiling` (runs the planned limiter chain; fails on `b034df8` with `assert 0.0 <= -0.2`).
- **Expected impact:** programme integrated loudness ~0.3 LU lower than today's renders; true peak at loudnorm's -1 dBTP target. Not re-measured on a real render (no footage here).
- **Status:** Implemented but not fully verified.
