### 2. M-001 Shipped config invalid off Windows — Verified and implemented
- Problem: `Path("D:/Gaming 2026").is_absolute()` is False on Linux, so `config/application.yaml` and `config/daily.yaml` fail validation and the whole suite cannot be collected off Windows. The C:-drive refusal was also a no-op off Windows (`PosixPath.drive` is empty).

### 3. M-002 NVENC→x264 proxy fallback always fails — Verified and implemented
- Evidence: integration jobs failed `PROXY_GENERATION_FAILED`; captured ffmpeg stderr: `x264 [error]: invalid preset 'p4'` / `Error setting preset/tune p4/(null)`. `config/rendering.yaml:81` proxy preset is `p4`; `resolve_codec` swaps the codec to libx264 but `codec_arguments` passed the preset through. x264 accepts only ultrafast…placebo or 0–9 (x264.h). So on any machine where NVENC is unavailable (driver issue, GPU busy, no NVIDIA) **every import fails** — the documented §95 fallback has never worked with the shipped config.
- Fix: `backend/media/proxy.py::codec_arguments` maps a `pN` preset to `veryfast` on software encoders (the same software preset `encoder.py` uses for its x264 fallback).
- Tests: new `test_a_hardware_preset_on_the_software_fallback_is_mapped`; real ffmpeg confirms `-preset p4` is refused and `veryfast` encodes. Integration `test_edl_pipeline.py`, `test_media_engine.py` now pass (were failing).
- Measurement (this container, CPU only): 10 s 1920×1080@60 synthetic clip → proxy with the fallback args in **7.25 s wall (≈1.38× realtime, 4 vCPU)**, 4.29 MB, h264 60/1 + aac, 10.000 s both streams (ffprobe). Not representative of the owner's i7.
