### WI-3 Research: colour handling from capture to YouTube
- YouTube's upload guidance names BT.709 for SDR and assumes BT.709 when tags are missing.
- Remotion `packages/renderer/src/options/color-space.tsx` at tag `v4.0.409` (the pinned version): default `default` in v4, `bt709` only from v5; `bt601` equals `default` (since 4.0.424); CLI flag `color-space`.
- Remotion `ffmpeg-args.ts` at `v4.0.409`: `bt709` emits `zscale=matrix=709:matrixin=709` plus `-colorspace/-color_primaries/-color_trc bt709`; `default`/`bt601` emit nothing (so FFmpeg's default BT.601 RGB→YUV, untagged).
- Local experiment (FFmpeg 6.1.1): a BT.601-tagged source keeps its tags through the cut→concat→encode path (`smpte170m` at every stage), so the gameplay path is sound; the overlay is not.

### WI-4 Experiment: caption colour error (BL-014)
