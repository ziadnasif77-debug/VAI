### WI-5 BL-018: research + experiment on BT.601 sources
- FFmpeg `vf_scale.c` (master): `out_color_matrix` restricts the negotiated format and output frames take `outlink->colorspace`, so the conversion also tags; `in_color_matrix` overrides the input tag.
- Experiment (#FFD400, lossless x264, 601-tagged source): read with a 709 matrix the unconverted 601 file gives 255,201,0 (the colour shift a 709 composite/player produces); after `scale=in_color_matrix=bt601:out_color_matrix=bt709` + 709 tags it gives 252,208,0 (true 709 reading of the 601 file is 253,210,0).
- Gotcha found: with `in_color_matrix` left on auto, an **untagged** input is treated as BT.601 by swscale, so a blanket `out_color_matrix=bt709` in `_frame_chain` would shift colours of untagged (normally BT.709) recordings. The fix must pass the probed source matrix per segment and leave 709/untagged sources alone.
- Status: **Verified finding awaiting implementation** (was a hypothesis).
