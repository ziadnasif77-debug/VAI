### WI-2 Config portability (BL-001, BL-002) {#wi-2}

- **Problem:** `config/application.yaml` and `config/daily.yaml` name
  `D:/Gaming 2026…`. `schema.py` checked `Path(x).is_absolute()`, which is
  false for `D:/…` on Linux → `CONFIG_INVALID` on every load → nothing runs off
  Windows. The `archive_directory` refusal also named the wrong key
  (`daily.output_directory`), and the `C:` system-drive rule never ran on Linux
  (`Path.drive` is empty there).
- **Action:** `_absolute_somewhere()` accepts host-absolute or drive-rooted
  Windows paths; the daily validator names its own field and reads the drive
  via `PureWindowsPath` on every host. `_move_to_archive` refuses a directory
  that is not absolute on this host (it would have `mkdir`-ed `./D:/…`); the
  existing handler records the refusal on the ledger row.
- **Files:** `backend/config/schema.py`, `backend/services/daily_producer.py`,

- **Tests:** new tests fail without the change (config: 9 failed/10 errors;
  daily: 1 failed) and pass with it (70 passed). **Status:** Verified and implemented.

### WI-3 Proxy NVENC → libx264 fallback was dead (BL-003) {#wi-3}

  `ffprobe`: h264 1280×720 30 fps + aac, duration 20.000 s. **Status:** Verified and implemented.

### WI-4 True-peak QA check; shipped chain misses −1 dBTP (BL-005, BL-006) {#wi-4}

- **Problem:** QA's decode pass already runs `ebur128=peak=true` but only
  parses integrated loudness — clipping is invisible.
- **Experiment (reproducible):** pink noise (a=0.9) + 997 Hz bursts, 20 s,
  through the shipped tail `loudnorm=I=-14:TP=-1:LRA=11,alimiter=limit=0.9661`
  (−0.3 dBFS), then AAC at 48 kHz:

  | Stage | Integrated | True peak |
  | --- | --- | --- |
  | PCM after mix tail | −14.0 LUFS | −0.6 dBTP |
  | AAC 384k (long-form preset) | −14.1 LUFS | −0.6 dBTP |
  | AAC 192k | −14.2 LUFS | −0.4 dBTP |
  | AAC 128k (Shorts/proxy bitrate) | −14.3 LUFS | −0.2 dBTP |

- **Action:** new `true_peak` technical check (warning, never blocking),
  threshold `qa.technical.thresholds.max_true_peak_dbtp` = 0.0 (real clipping),
  not −1.0, so it does not warn on every current render. The −1 dBTP miss is
  logged as BL-006 for the owner: fixing it changes every video's audio.
- **Files:** `backend/qa/technical.py`, `backend/config/schema.py`,
  `config/qa.yaml`, `tests/integration/test_qa.py` (+3 incl. a clipped clip).
- **Tests:** `test_qa.py` + config tests: pass. **Status:** Verified and implemented.
